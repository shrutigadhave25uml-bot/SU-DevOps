# 5. Story Point Estimation and Sprint Planning

## Example story point scale
| Points | Relative complexity |
|---:|---|
| 1 | Very easy |
| 2 | Easy |
| 3 | Moderate |
| 5 | Difficult |
| 8 | Very difficult |
| 13 | Highly complex |

Story points are relative estimates, not hours. The team should use Planning Poker and agree on the final estimates.

## Example three-sprint plan

### Sprint 1 — Project setup and student records
**Goal:** Set up the repository and deliver core student management.
- Create project structure and initial interface.
- Implement add, search, edit, and delete student records.
- Add sample data and browser persistence.
- Test form validation and list filtering.

**Deliverable:** Working student management module.

### Sprint 2 — Courses, attendance and marks
**Goal:** Track course enrollment, attendance, and assessment results.
- Create and display courses.
- Record attendance by date.
- Enter marks and calculate percentages/grades.
- Test validation and related-record behavior.

**Deliverable:** Working academic record modules.

### Sprint 3 — Dashboard, reports and documentation
**Goal:** Provide summaries and prepare a demonstrable MVP.
- Build dashboard summary cards.
- Create performance report and CSV export.
- Test responsive layout and main user flows.
- Update README, backlog, and project documentation.

**Deliverable:** Demonstrable front-end MVP and documentation.

## Sprint planning checklist
- Select backlog items based on priority and capacity.
- Agree a clear Sprint Goal.
- Review acceptance criteria.
- Identify dependencies and risks.
- Confirm how the team will demonstrate completion.
