# 8. Agile Framework Comparison

| Framework | Main idea | Advantages | Considerations for this mini-project |
|---|---|---|---|
| Scrum | Time-boxed sprints, defined accountabilities and events | Clear goals, regular review and feedback | Suitable for a student team delivering a planned MVP |
| Kanban | Visualize workflow and limit work in progress | Flexible flow and visible bottlenecks | Useful for ongoing support and small continuous tasks |
| Extreme Programming (XP) | Engineering practices such as pair programming, testing and frequent integration | Strong focus on code quality and feedback | XP practices can improve testing and maintainability |
| Lean Development | Reduce waste and optimize value flow | Encourages simplicity and efficient delivery | Helpful for keeping MVP scope focused |
| Large Scale Scrum (LeSS) | Applies Scrum principles across multiple teams | Coordinates related teams with shared product focus | Usually more structure than a small student team needs |
| Scaled Agile Framework (SAFe) | Coordinates agile work across a large enterprise | Planning and alignment across many teams | Too heavyweight for a small mini-project |
| Scrum@Scale | Connects multiple Scrum teams through scaling patterns | Supports coordination across teams | More useful when several teams work on one product |

## Recommendation
For a small student team, Scrum is a reasonable starting framework because the assignment asks for a Product Backlog, Sprint Planning, Scrum roles, and Scrum ceremonies. Kanban can also be used to visualize the team's day-to-day work. The recommendation should be revisited if the team size or project constraints change.
